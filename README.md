# Бизнес-игра «Человек + ИИ»

Учебная платформа для акселератора 10 декабря 2026 года. Человек ставит задачи и принимает решения, ИИ помогает команде с расчётами, проверками и передачей результатов. Все данные и ответы синтетические; внешние модели и платформы не вызываются.

[Открыть игру](https://fot-manager-training.github.io/zero-human-company/) · [Рабочее пространство GigaCoWork](https://fot-manager-training.github.io/zero-human-company/#cowork) · [Скачать архитектуру SVG](https://fot-manager-training.github.io/zero-human-company/architecture.svg)

## Что есть в интерфейсе

- **Ход игры**: карта с десятью помощниками. Неактивные карточки свёрнуты; участники работы и доставки раскрываются. Бегущие персонажи несут данные между ролями. Пояснения находятся внутри карточек, сообщения — в отдельной полосе.
- **GigaCoWork**: учебный интерфейс по предоставленному скриншоту. Здесь выбирают пространство стола, пишут поручение и проверяют результат. Ссылка на отдельное пространство: `?table=3#cowork` (номер 1–10).
- **Показать ввод за столами**: автопоказ постепенно печатает и отправляет десять поручений, ждёт помощь ИИ, показывает уточняющий вопрос участника и развёрнутый ответ помощника. Набор и паузы чтения увеличены. Поддерживаются пауза, остановка и скорости ×1–×16.
- Рабочий экран GigaCoWork закреплён в высоте окна. История переписки прокручивается внутри своей области, заголовок и поле ввода сохраняют положение. Переходы между столами и новые ответы не прокручивают страницу.
- **Диалог агентов** и **журнал событий**: полная история передачи результатов и решений. Фильтр по столу и экспорт JSON.
- **Как это работает**: архитектурная схема пути от участника через GigaCoWork, API и оркестратор к агентам, данным и экрану.

Пульт управления и отдельные терминалы столов удалены. Все поручения вводятся через рабочие пространства GigaCoWork. Параметры синтетического заказа берутся из сценария; на экране остаются только действия воспроизведения и согласование закупки человеком.

## Сценарий

Гендиректор запускает две ветки: партнёры → финансы и дизайн → бренд-контроль. Закупки ждут тираж, смету и одобренный макет. Далее: производство → логистика → приёмка → выдача.

Список содержит 108 записей, 100 уникальных партнёров и 8 дублей. Резерв по умолчанию 10%: 110 подарков. Шар — 420 ₽, упаковка — 80 ₽/шт., доставка — 5 000 ₽. Итог: 60 000 ₽ при лимите 80 000 ₽. Выдача: по 10 подарков каждому из десяти столов, 10 шт. в резерве.

Обычный запуск останавливается перед закупкой для решения пользователя. В автопоказе ввода за столами отдельно воспроизводится решение капитана; событие помечено как синтетическое. Превышение бюджета не согласуется автоматически.

Уточняющий диалог после результата — подготовленный сценарий интерфейса. Он не создаёт повторную задачу в движке и не имитирует реальный вызов LLM. Основные десять поручений отправляются через общий API и учитываются в журнале.

## Серверная версия

Нужен Python 3.12+, сторонних runtime-зависимостей нет:

```bash
cd /workspace/zero-human-company
python3 server.py --port 8000
```

Существующий checkout уже изолирован облачной задачей; отдельный worktree не требуется. SQLite хранится в игнорируемом `.local/game.sqlite3`; другой путь задаётся через `--db`. Все подключённые экраны серверной версии работают с одной общей игрой. Перезапущенный прогон возобновляется вручную.

Для размещения Python-сервиса используйте `--host 0.0.0.0`, HTTPS reverse proxy и разграничение доступа. Текущий код предназначен для учебного стенда; перед открытым мероприятием нужны авторизация ведущего и участников, ограничения запросов и проверка реального коннектора.

## GitHub Pages

Workflow `Deploy demo to GitHub Pages` собирает самостоятельную браузерную версию:

```bash
python3 scripts/build_pages.py
python3 -m http.server 8002 --directory site
```

Статическая версия использует локальный игровой движок и localStorage, без общего сервера между устройствами. Рабочие пространства десяти столов относятся к одной локальной сессии браузера. Реальные GigaCoWork и GigaNetwork не подключены. Примеры результатов и передачи данных при сборке получаются из того же Python-движка. URL ресурсов содержат версию содержимого для обновления кеша.

## Входной REST-контракт

Серверная версия принимает сообщения в `POST /api/integrations/gigacowork`. Для включения задайте `GAME_WEBHOOK_TOKEN` через защищённые настройки окружения. Без него ответ 503, при неверном Bearer — 401. Это адаптер REST, а не готовый MCP-коннектор; подключение к настоящему GigaCoWork отдельно не проверено.

```json
{"table_id":1,"text":"Помоги подготовить подарки партнёрам","request_id":"table-1-order-001"}
```

`table_id` — 1–10; `text` — 1–4000 символов. Повторный `request_id` не создаёт вторую задачу в текущей игре. Используйте уникальные ID для разных сообщений. Принятие запроса не означает завершения агента.

Рабочие пространства используют `/api/messages`. `/api/state` возвращает общий снимок, `/api/health` — состояние сервера. Служебные `/api/action` и `/api/config` используются эмулятором воспроизведения и тестами; отдельного пользовательского пульта для них нет.

## Проверка

```bash
python3 -m unittest discover -s tests -v
```

Проверяются расчёты, зависимости ролей, бюджет, решение человека, повторная доставка сообщения, восстановление SQLite, пауза и изменение скорости.

Браузерные проверки требуют Playwright и Chromium:

```bash
GAME_TEST_URL=http://127.0.0.1:8002/ node tests/browser.cjs
GAME_TEST_URL=http://127.0.0.1:8002/ node tests/collaboration.cjs
GAME_TEST_URL=http://127.0.0.1:8002/ node tests/simulation.cjs
GAME_TEST_URL=http://127.0.0.1:8002/ node tests/cowork-demo.cjs
```

Тесты сбрасывают целевую игру, поэтому используйте отдельную сессию или тестовую базу. Автопоказ проверяет набор, паузу, все десять поручений, расширенные уточняющие диалоги, неподвижность страницы и поля ввода. Проверка совместной работы также контролирует свёрнутые карточки, отсутствие наложений и мобильную вёрстку. GitHub Actions запускает unit/API-тесты, проверяет синтаксис JavaScript, собирает Pages и после деплоя проверяет доступность страницы и ресурсов.


## Расширенное объяснение и оформление

Раздел «Как это работает» содержит четыре самостоятельные схемы: состав стенда, BPMN-цепочку десяти ролей, последовательность одного поручения и состояния помощника. Есть выбор примеров партнёров, финансов и закупок, таблица входов/выходов десяти столов и карточки состояний. Каждая схема скачивается как SVG.

Генератор: `python3 scripts/build_diagrams.py`. BPMN-нотация используется для объяснения процесса; исполняемые зависимости остаются в `server.py` и браузерном движке. Из приложенного примера заимствована структура объяснения, а роли, проверки и числа соответствуют игре про подарки.

Визуальный стиль: центрированная белая страница, верхняя навигация, фактурное синее кольцо со стеклянной половиной, голубые градиенты карточек и лаймовые кнопки. Изображение кольца находится в `static/hero-ring.png`. Рабочее пространство GigaCoWork сохраняет закреплённую вёрстку чата.

Браузерная проверка схем, примеров, загрузки изображений, мобильного экрана и скачивания: `GAME_TEST_URL=<тестовый адрес> node tests/guide.cjs`.
